# AI Text Classifier API

A Flask API for classifying SMS messages as **spam** or **not spam**, trained on
the real [UCI SMS Spam Collection](https://archive.ics.uci.edu/dataset/228/sms+spam+collection).
Training is an explicit offline task; the web application only loads artifacts
and performs inference.

## Architecture

```text
ai-text-classifier/
├── app/
│   ├── __init__.py              # Flask factory; loads one predictor per worker
│   ├── routes.py                # HTTP endpoints and input validation only
│   └── services/
│       ├── __init__.py
│       └── predictor.py         # Loads saved artifacts; transforms and predicts
├── ml/
│   ├── __init__.py
│   ├── train.py                 # Offline training pipeline
│   ├── evaluate.py              # Held-out metrics and optional JSON report
│   └── utils.py                 # Dataset validation, splitting, artifact I/O
├── data/
│   ├── sms_spam.csv             # Real, checked-in dataset (label,text)
│   └── README.md                # Source, conversion, attribution, license
├── models/
│   ├── model.pkl                # Generated by training, not versioned
│   ├── vectorizer.pkl           # Generated by training, not versioned
│   └── metadata.json            # Dataset hash, exact holdout, artifact checksums
├── tests/
├── run.py
├── requirements.txt
├── requirements-dev.txt
├── pyproject.toml
└── README.md
```

```text
OFFLINE: CSV → validate/deduplicate → stratified train/test split
           → fit vectorizer and classifier on training rows only
           → evaluate unseen test rows → save artifacts + metadata

ONLINE:  POST /predict → validate JSON → saved vectorizer.transform
           → saved model.predict → JSON response
```

There is no training, downloading, or dataset access during API startup or a
prediction request. Missing, corrupt, or incompatible artifacts produce a clear
startup error instead of silently training a replacement model.

## Quick start

Use **Python 3.10+**. Run these commands from the repository root:

```bash
git clone https://github.com/devvadams/ai-text-classifier.git
cd ai-text-classifier
python -m venv .venv
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt

# 1. Train offline. The real dataset is already included; no download is needed.
python -m ml.train

# 2. Optionally reproduce the held-out metrics and write a JSON report.
python -m ml.evaluate --output reports/evaluation.json

# 3. Start the API using the saved model.
python run.py
```

The development server listens on `0.0.0.0:5000` (all interfaces); locally, visit
`http://127.0.0.1:5000/`. Debug mode is off by default. The Flask development
server is not a production WSGI server.

### Configuration

| Setting | Default | Purpose |
| --- | --- | --- |
| `MODEL_DIR` environment variable | Repository's `models/` directory | Artifact bundle to load at API startup |
| `PORT` environment variable | `5000` | Port used by `python run.py` |
| Flask `MAX_TEXT_LENGTH` config | `10000` characters | Maximum input text length |
| Flask `MAX_CONTENT_LENGTH` config | `65536` bytes | Maximum HTTP request body |

Default dataset/model paths are anchored to the repository, not the current
working directory. Explicit CLI paths are relative to your working directory.
Flask configuration can also be supplied to `create_app({...})` for tests or
embedding the application.

To use an alternative dataset and artifact directory:

```bash
python -m ml.train --data data/sms_spam.csv --model-dir models --test-size 0.2 --seed 42
python -m ml.evaluate --data data/sms_spam.csv --model-dir models
```

For another artifact location, set `MODEL_DIR` when starting the API. Deploy the
**entire bundle** (`model.pkl`, `vectorizer.pkl`, and `metadata.json`) together.
Retrain after changing scikit-learn versions, and restart workers after replacing
artifacts. Training and artifact replacement should happen offline, not while
workers are starting. Only load artifacts you trust: Joblib/pickle files can
execute code when deserialized; checksums are not an authenticity guarantee.

## Dataset and model

`data/sms_spam.csv` contains **5,574 messages**: 4,827 `ham` (legitimate) messages
and 747 `spam` messages. The CSV preserves the source messages and labels; see
[data/README.md](data/README.md) for provenance, checksums, and the dataset's
**CC BY 4.0** license. The project's MIT license applies to the code, not the
dataset.

The loader requires `label` and `text` columns, rejects empty messages, unknown
labels, and conflicting labels for identical trimmed messages, and removes
duplicate messages **before** splitting. This leaves **5,160 unique messages**.
The default seeded, stratified 80/20 split produces 4,128 training messages and
1,032 test messages.

The baseline is a `CountVectorizer` with word unigrams/bigrams and a
`MultinomialNB(alpha=1.0)` classifier. The vectorizer is fitted only on training
messages, preventing vocabulary leakage. Internal labels are `ham`/`spam`; the
API maps `ham` to `not spam` to preserve the original response contract.

Training records the dataset SHA-256 and the exact held-out row indices in
`metadata.json`. Evaluation verifies the same dataset and artifact pair and
scores those saved rows—it does not refit or create a new random split.

### Verified baseline

With the pinned dependencies, seed `42`, and a `0.2` test fraction:

| Metric | Result |
| --- | ---: |
| Held-out accuracy | 98.16% |
| Spam precision | 97.39% |
| Spam recall | 87.50% |
| Spam F1 | 92.18% |

Confusion matrix (rows = true label, columns = predicted label):

| | Predicted ham | Predicted spam |
| --- | ---: | ---: |
| True ham | 901 | 3 |
| True spam | 16 | 112 |

`ml.evaluate` prints accuracy, per-class precision/recall/F1, macro and weighted
averages, and a labeled confusion matrix. Generated bundles and `reports/` are
ignored by Git; recreate them using the commands above.

These are results on a historical SMS holdout, **not** a guarantee for modern
SMS, email, other languages, or adversarial messages. False positives and missed
spam are possible. Use separate validation data if tuning model parameters, and
evaluate fresh representative data before deploying the classifier.

## API

### `GET /`

Returns `AI Text Classifier API is running!`. The application only starts
successfully when its model bundle is available.

### `POST /predict`

Send an `application/json` object with a non-empty string `text`:

```bash
curl -X POST http://127.0.0.1:5000/predict \
  -H 'Content-Type: application/json' \
  -d '{"text":"Are we still meeting for lunch tomorrow?"}'
```

```json
{
  "input": "Are we still meeting for lunch tomorrow?",
  "prediction": "not spam"
}
```

The input is echoed unchanged; `prediction` is either `spam` or `not spam`.

- **400** with a JSON `error`: missing/malformed/non-object JSON, missing `text`,
  non-string or blank `text`, or text exceeding the character limit.
- **413** with a JSON `error`: request body exceeds the byte limit.

No authentication is included. Add authentication, rate limiting, appropriate
logging/redaction, and a production WSGI server before exposing it publicly.

## Development and verification

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
ruff check .
ruff format --check .
```

Tests train against the real dataset in temporary directories. They cover input
validation, spam/ham predictions, artifact loading/caching, startup failures,
dataset validation, duplicate/vocabulary leakage, exact holdout evaluation,
corrupt/incompatible bundles, and CLI execution from a different directory.
